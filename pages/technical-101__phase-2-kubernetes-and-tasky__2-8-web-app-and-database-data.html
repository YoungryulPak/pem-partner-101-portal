2.8 Web app and database data

Time 15 minutesAWS cost None beyond the running labNeeds 2.7 completedSource script Technical_Exercise/phase2_k8s_tasky/p2demo/216_Web_App_DB_Data.sh

Goal

Use the web application, then prove from the database side that the exact record you created is stored there.

Why it matters

Two separate claims ("the app works", "the database has data") are weaker than one linked proof. You create a record with a unique marker in the browser, then find the same marker in the database.

Before you start

Phase 1 is deployed. kubectl points at your cluster (see 2.1 Deploy EKS with Terraform). Run the commands from the phase2_k8s_tasky folder unless a step says otherwise.

export INSTANCE_ID="<YOUR_INSTANCE_ID>"
export KEY_PATH="../phase1_vm_mongodb/wiz-exercise-key.pem"
export ALB_HOST="<YOUR_LOAD_BALANCER_ADDRESS>"
export MARKER="LabDemo-$(date +%s)"
echo "$MARKER"
VariableMeaning
ALB_HOSTThe address from 2.7 Ingress and load balancer
MARKERA unique text that no other record has

Steps

Step 1: use the application

Open http://$ALB_HOST/ in a browser. Create an account, sign in and add a to-do whose text contains the marker printed above.

Step 2: log in to the database VM

IP=$(aws ec2 describe-instances --instance-ids "$INSTANCE_ID" \
  --query 'Reservations[].Instances[].PublicIpAddress' --output text)
ssh -i "$KEY_PATH" "ubuntu@$IP"

Step 3: open the database shell

mongo --username taskyAdmin --authenticationDatabase admin go-mongodb

Enter the password when asked. go-mongodb is the application's database.

PartMeaning
--usernameThe admin user
--authenticationDatabase adminWhere that user is defined
go-mongodbSelect this database after login

Step 4: find your record

db.getCollectionNames()
db.user.find().pretty()
db.todos.find().pretty()
CommandWhat it does
db.getCollectionNames()Lists the collections, so you can see the real names
db.user.find()Shows stored users
db.todos.find()Shows stored to-dos

If the to-do collection has another name in your build, use the name from the first command.

Caution: the user records may contain password hashes. Do not copy them anywhere.

Expected: a to-do whose text contains your marker.

Verify

The marker you typed in the browser appears in the database.

Troubleshooting

SymptomLikely causeFix
Browser shows an error on sign-upThe app cannot reach the databaseCheck 2.4 Database access through an environment variable
Marker not foundLooking at the wrong collection or databaseUse db.getCollectionNames() and check the database name

Clean up

Delete the test account's data if you wish; destroying the VM removes the database.

Check yourself

  1. Why use a unique marker instead of looking at any record?
  2. What risk does a database with user records create if its backup is public (see 1.8 Public bucket: read and list)?
