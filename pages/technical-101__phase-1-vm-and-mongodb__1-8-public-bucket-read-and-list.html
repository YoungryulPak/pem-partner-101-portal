1.8 Public bucket: read and list

Time 10 minutesAWS cost NoneNeeds 1.7 completedSource script Technical_Exercise/phase1_vm_mongodb/p1demo/130_Daily_MongoDB_Backup.sh; s3.tf

Goal

Prove that anyone on the internet can list and read the backup bucket without a login.

Why it matters

The bucket is configured on purpose with public read and public listing. Backup files can hold user data and password hashes. So an open bucket is both a data exposure and a posture error. The posture error is that "block public access" is turned off. An outside-in scan finds this with no access to your account at all. That is the view SecurityScorecard gives. See Own external exposure (SecurityScorecard).

Before you start

export BUCKET="<YOUR_BACKUP_BUCKET>"

Steps

Step 1: read the bucket's public-access settings

aws s3api get-public-access-block --bucket "$BUCKET"
PartMeaning
aws s3apiLow-level S3 commands
get-public-access-blockShow the four "block public access" switches

Expected: all four values are false, which means nothing blocks public access.

Step 2: ask the cloud for its verdict

aws s3api get-bucket-policy-status --bucket "$BUCKET"

Expected: "IsPublic": true.

Step 3: list the bucket with no credentials

aws s3 ls "s3://$BUCKET" --no-sign-request
PartMeaning
--no-sign-requestSend the request anonymously, with no credentials

Expected: the list of backup objects. This is what any stranger would see.

Step 4: read one object anonymously

aws s3 cp "s3://$BUCKET/<OBJECT_KEY>" ./downloaded-backup --no-sign-request
PartMeaning
aws s3 cpCopy an object to your machine
<OBJECT_KEY>A name from the Step 3 listing
Warning: a real backup would contain sensitive data. Delete the downloaded file when you are done.

You can also open the bucket's public URL from terraform output backup_bucket_public_url in a browser and see the same listing as XML.

Verify

Settings (1), the verdict (2) and live anonymous access (3 and 4) all agree.

Fix it

Turn public access off.

aws s3api put-public-access-block --bucket "$BUCKET" \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
aws s3api delete-bucket-policy --bucket "$BUCKET"
PartMeaning
put-public-access-blockSwitch the four blocks on
delete-bucket-policyRemove the policy that allows public read and list

Run Step 3 again: it should now fail with access denied. Terraform still describes the open bucket, so change s3.tf before the next terraform apply.

Troubleshooting

SymptomLikely causeFix
Step 3 says access deniedThe bucket is already closedExpected after the fix
Step 3 is emptyNo backup yetRun the backup in 1.7 Daily backup to object storage

Clean up

Delete the downloaded file. Bucket removal is part of Cost, safety and cleanup.

Check yourself

  1. Which of the three checks needs no access to the account?
  2. Why does a public backup bucket matter even if the database itself is protected?
