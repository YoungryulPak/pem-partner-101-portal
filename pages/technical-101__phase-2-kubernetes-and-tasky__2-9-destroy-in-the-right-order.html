2.9 Destroy in the right order

Time 20 to 30 minutesAWS cost Stops the hourly chargesNeeds You have finished the labs you want to doSource script Technical_Exercise/phase2_k8s_tasky guide, destroy section

Goal

Remove everything you built. Use the order that avoids leftovers and stuck deletions. Confirm that nothing is still billing.

Why it matters

Cloud resources depend on each other. The load balancer was created by a controller inside the cluster, not by Terraform, so Terraform does not know about it. If you destroy the network first, the load balancer blocks the deletion and keeps billing. Always remove later layers first.

Before you start

You are in the repository root. Finish any lab you still want to do (Phases 3 and 4 build on this).

Steps

Step 1: delete the Kubernetes objects

kubectl delete -f phase2_k8s_tasky/k8s/
PartMeaning
kubectl delete -fDelete every object defined in the files of that folder

This removes the Ingress, which makes the controller delete the load balancer. Wait a few minutes, then check:

aws elbv2 describe-load-balancers --query 'LoadBalancers[].LoadBalancerName'

Expected: no Tasky load balancer.

Step 2: destroy Phase 2

cd phase2_k8s_tasky/terraform
terraform destroy
PartMeaning
terraform destroyLists everything it will delete, asks for yes, then deletes it

If the image repository still holds images, empty it first or enable force delete.

Step 3: destroy Phase 1

cd ../../phase1_vm_mongodb
terraform destroy

If the backup bucket is not empty, empty it first (aws s3 rm "s3://$BUCKET" --recursive).

PartMeaning
aws s3 rm ... --recursiveDelete every object in the bucket

Step 4: look for leftovers

In the cloud console (or with the CLI) check for load balancers, volumes, snapshots, network interfaces, key pairs and buckets created by the labs, and delete any that remain. Also delete the controller policy AWSLoadBalancerControllerIAMPolicy if you created it.

Verify

No lab resources remain and the account's cost view shows no running lab services.

Troubleshooting

SymptomLikely causeFix
Destroy hangs on a subnet or VPCA load balancer or network interface remainsDelete the load balancer (Step 1), wait, retry
Bucket not emptyBackups still in itEmpty the bucket, retry

Clean up

This page is the clean-up. See also Cost, safety and cleanup.

Check yourself

  1. Why can't Terraform destroy the load balancer for you?
  2. In what order do you destroy the phases, and why?
