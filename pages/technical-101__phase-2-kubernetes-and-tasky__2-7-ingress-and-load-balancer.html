2.7 Ingress and load balancer

Time 20 to 30 minutesAWS cost A load balancer bills by the hourNeeds 2.4 completed; eksctl and helm installedSource script Technical_Exercise/phase2_k8s_tasky/p2demo/215_Exposed_K82_Ingress_ALB.sh

Goal

Expose the application to the internet through a Kubernetes Ingress and a cloud load balancer, and prove it answers from outside.

Why it matters

Making an application reachable is the moment it becomes part of the external attack surface. The load balancer's address is what an outside-in scan sees. See Own external exposure (SecurityScorecard). Three independent sources should agree with each other: the Ingress spec, the cloud's own record of the load balancer, and a real response from the internet.

Before you start

Phase 1 is deployed. kubectl points at your cluster (see 2.1 Deploy EKS with Terraform). Run the commands from the phase2_k8s_tasky folder unless a step says otherwise.

You need eksctl and helm (for example brew install eksctl helm).

Steps

Step 1: let the cluster create load balancers

The AWS Load Balancer Controller turns an Ingress into a cloud load balancer.

eksctl utils associate-iam-oidc-provider --region us-east-1 \
  --cluster wiz-exercise-eks --approve

curl -o iam_policy.json https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v2.7.2/docs/install/iam_policy.json
aws iam create-policy --policy-name AWSLoadBalancerControllerIAMPolicy \
  --policy-document file://iam_policy.json

eksctl create iamserviceaccount \
  --cluster=wiz-exercise-eks --region=us-east-1 \
  --namespace=kube-system --name=aws-load-balancer-controller \
  --attach-policy-arn=arn:aws:iam::<YOUR_ACCOUNT_ID>:policy/AWSLoadBalancerControllerIAMPolicy \
  --approve

helm repo add eks https://aws.github.io/eks-charts
helm repo update
helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=wiz-exercise-eks \
  --set serviceAccount.create=false \
  --set serviceAccount.name=aws-load-balancer-controller
CommandWhat it does
eksctl utils associate-iam-oidc-providerLets pods assume cloud roles through the cluster's identity provider
aws iam create-policyCreates the permissions the controller needs
eksctl create iamserviceaccountCreates a service account tied to that policy
helm install ...Installs the controller into kube-system

Step 2: create the Ingress

kubectl apply -f k8s/05_ingress.yaml
kubectl get ingress -n tasky -w

The Ingress asks for an internet-facing load balancer (alb.ingress.kubernetes.io/scheme: internet-facing) that sends traffic to the service on port 8080. Wait 2 to 3 minutes until the ADDRESS column fills in, then press Ctrl+C.

Step 3: record the address

ALB_HOST=$(kubectl get ingress tasky-ingress -n tasky \
  -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')
echo "$ALB_HOST"

Step 4: ask the cloud about the load balancer

aws elbv2 describe-load-balancers \
  --query "LoadBalancers[?DNSName=='$ALB_HOST'].{Name:LoadBalancerName,State:State.Code,Scheme:Scheme}"

Expected: state active and scheme internet-facing.

Step 5: reach it from the internet

curl -s -m 5 -o /dev/null -w '%{http_code}\n' "http://$ALB_HOST/"
PartMeaning
-sSilent
-m 5Give up after 5 seconds
-o /dev/nullThrow away the page
-w '%{http_code}\n'Print only the HTTP status

Expected: 200. Open http://$ALB_HOST/ in a browser to see the Tasky login page.

Verify

The Ingress has an address, the cloud shows an active internet-facing load balancer, and a real request returns 200.

Troubleshooting

SymptomLikely causeFix
ADDRESS stays emptyController not runningkubectl get pods -n kube-system and check the controller pods
Status 502 or 503Pods not readyCheck 2.4 Database access through an environment variable
AccessDenied creating the policyLab user lacks IAM permissionsAdd IAM permissions for the lab user

Clean up

Delete the Ingress before destroying the cluster, or the load balancer is left behind. See 2.9 Destroy in the right order.

Check yourself

  1. Why check three sources instead of one?
  2. What does internet-facing change about who can reach the application?
