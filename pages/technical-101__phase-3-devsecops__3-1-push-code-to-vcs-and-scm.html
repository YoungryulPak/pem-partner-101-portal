3.1 Push code to VCS and SCM

Time 20 minutesAWS cost NoneNeeds Phases 1 and 2 files on your machine; a GitHub account; git and the GitHub CLI (gh) installedSource script Technical_Exercise/phase3_devsecops/Phase3 guide, 310_Push_Code_Config_VCS_SCM.sh

Goal

Put the lab's code and configuration in a private GitHub repository without leaking any secret.

Why it matters

Version control, or VCS, and source code management, or SCM, are where pipelines start. They are also where secrets leak. A key file, a Terraform state file or a Kubernetes Secret stays in history once it is committed, even just once. The first job is to decide what must never be committed.

Before you start

  • A private repository on GitHub. Make it private, because the lab files describe your own infrastructure. Example name: lab-security-exercise.
  • You are in the root folder that holds phase1_vm_mongodb, phase2_k8s_tasky and phase3_devsecops.

Steps

Step 1: start a local repository

git init
git add -A
CommandWhat it does
git initTurns the folder into a git repository
git add -AStages every file, including new and deleted ones

Step 2: check for secrets before committing

git status | grep -E "terraform.tfvars|\.pem|01_secret\.yaml|terraform\.tfstate|iam_policy"
PartMeaning
git statusShow what is staged
`grep -E "abc"`Keep lines that match any of these patterns

Expected: no output. If something matches, create a root .gitignore containing those patterns (see root_gitignore_addition.txt in phase3_devsecops), then run git add -A again.

Warning: a secret that is committed once is in the history even if you delete it later. Fix it before the first commit.

Step 3: move the workflows to the repository root

GitHub only runs workflows found in .github/workflows at the root.

cp -r phase3_devsecops/.github .
rm -rf phase3_devsecops/.github
PartMeaning
cp -rCopy a folder with everything in it
rm -rfDelete a folder. Check the path before you press Enter

Step 4: commit and push

git add -A
git commit -m "Initial commit: security exercise (Phases 1-3)"
git branch -M main
git remote add origin https://github.com/<YOUR_ACCOUNT>/<YOUR_REPO>.git
git push -u origin main
CommandWhat it does
git commit -mSave the staged files with a message
git branch -M mainName the branch main
git remote add origin <url>Tell git where the shared repository is
git push -u origin mainUpload and remember the upstream branch

Remove a leftover workflow from the original application template if it exists:

git rm tasky-main/.github/workflows/build-and-publish.yml
git commit -m "Remove unused legacy workflow"
git push

Step 5: prove it landed

git remote -v
git log --oneline -5
echo "local:  $(git rev-parse HEAD)"
echo "remote: $(git ls-remote origin main | awk '{print $1}')"
gh repo view <YOUR_ACCOUNT>/<YOUR_REPO> --json visibility,pushedAt
CommandWhat it does
git remote -vShow the remote address
git log --oneline -5Last five commits, one line each
git rev-parse HEADThe local commit ID
git ls-remote origin mainThe commit ID the remote has for main
gh repo view ... --json visibility,pushedAtGitHub's own record: visibility and last push time

Verify

Local and remote commit IDs are identical and the repository is private.

Troubleshooting

SymptomLikely causeFix
Authentication failedNo git credentialsSign in with gh auth login
A secret file shows in git statusNot in .gitignoreAdd it and re-stage (before committing)
Workflows do not appear on GitHub.github is not at the rootRedo Step 3

Clean up

Delete the repository on GitHub when you finish the labs.

Check yourself

  1. Why is a committed secret hard to remove?
  2. Why compare the local and remote commit IDs?
