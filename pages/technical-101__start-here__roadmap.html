Roadmap

Technical 101 is a self-guided, hands-on track for engineers. You build a small environment. It runs in the cloud, in your own account. You run every command yourself. You see what each command does. The labs are tested in a cloud environment. The examples and commands use Amazon Web Services, often called AWS. The security ideas apply to other clouds too. Only the commands differ. Along the way, you meet the real security problems that exposure management tools look for.

Warning: the environment is intentionally vulnerable. Use a dedicated sandbox cloud account. These examples use AWS. Never use a production account. Destroy everything when you finish. See Cost, safety and cleanup.

The four phases

PhaseYou buildSecurity ideas you meet
1. VM and MongoDBA VM with an outdated OS and database, daily backups to object storageCloud posture (CSPM), identity entitlements (CIEM), data exposure, outdated software
2. Kubernetes and TaskyA private Kubernetes cluster running a containerized to-do app behind a load balancerWorkload and container security, Kubernetes posture (KSPM), over-privileged service accounts
3. DevSecOpsCode in version control, pipelines that scan and deployIaC scanning, container scanning, pipeline and repository security
4. Detection and responseLog analysis, open-source scanners, a dashboard, attack simulationsDetection, triage, preventive controls, incident response

What each lab page gives you

Goal, why it matters, prerequisites, numbered steps with every command explained, expected output, a verification step, troubleshooting and cleanup. See How to read a lab page.

How it connects to the solutions

Each weakness you create is also something the exposure-management tools find:

  • Outside-in: an open SSH port or public bucket is what SecurityScorecard's external view reports.
  • Inside-out: the over-permissive IAM role or cluster-admin binding is what Mondoo flags and helps fix.
  • Validation: Alt Security shows whether such a weakness can be exploited.

Where it helps, lab pages link back to PEM and the four perspectives.

Recommended order

  1. Prerequisites and cloud account setup
  2. How to read a lab page and Cost, safety and cleanup
  3. Phase 1 from 1.1 onward, then Phases 2 to 4 in order. Each phase builds on the previous one.

This track is independent: you do not need the Sales, Presales, Service or Support pages to follow it.
