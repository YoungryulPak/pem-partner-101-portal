Prerequisites and cloud account setup

Time 30 minutesAWS cost None for setupNeeds A laptop with admin rights and a cloud sandbox account (AWS in the examples)

Goal

Have every tool installed. Sign in to the right cloud account before the first lab. The labs run in a cloud environment, and the examples use AWS. So this page installs the AWS tools and signs in to an AWS account. If you use another cloud, install that cloud's command-line tool instead.

What you need

ToolUsed for
Cloud account (sandbox); AWS in the examplesWhere the lab runs
AWS CLI v2 (the cloud's command-line tool)Talk to AWS from the terminal
TerraformCreate the infrastructure from code
kubectlControl the Kubernetes cluster (Phase 2)
DockerBuild the container image (Phase 2)
GitVersion control (Phase 3)
An SSH clientLog in to the VM (built into macOS and Linux)

Step 1: check the tools

aws --version
terraform version
kubectl version --client
docker --version
git --version
CommandWhat it does
aws --versionPrints the AWS CLI version. It must start with aws-cli/2
terraform versionPrints the Terraform version and warns if a newer one exists
kubectl version --clientPrints only the local client version. The --client flag avoids contacting a cluster
docker --versionConfirms Docker is installed
git --versionConfirms Git is installed

Expected: each command prints a version. If one says "command not found", install it first.

Step 2: sign in to the sandbox cloud account (AWS)

Create an access key for a dedicated lab user in the sandbox account, then:

aws configure
PromptEnter
AWS Access Key IDThe lab user's key ID
AWS Secret Access KeyThe lab user's secret
Default region nameus-east-1 (the labs assume this region)
Default output formatjson
Warning: never paste keys into chat, tickets or files that you commit. If a key leaks, delete it in the AWS console immediately.

Step 3: confirm which cloud account you are in

aws sts get-caller-identity
PartMeaning
stsThe AWS Security Token Service
get-caller-identityReturns who the CLI is acting as. It needs no permissions

Expected output (example):

{
    "UserId": "AIDAEXAMPLE",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/lab-user"
}

Check that Account is your sandbox account number. If it is not, stop.

Troubleshooting

SymptomLikely causeFix
Unable to locate credentialsaws configure not runRun it again
InvalidClientTokenIdWrong or deleted keyCreate a new key and reconfigure
AccessDenied on later labsLab user lacks permissionsGive the lab user the permissions your sandbox policy allows for EC2, VPC, IAM, S3 and EKS
