4.2 Open-source CNAPP: Prowler and Kubescape

Time 30 minutesAWS cost NoneNeeds Phases 1 and 2 deployed; kubectl pointing at the clusterSource script Technical_Exercise/phase4_ai_cnapp_incident/oss_cnapp

Goal

Scan the cloud account and the cluster with two open-source tools and check that they find the weaknesses you planted.

Why it matters

Commercial cloud security platforms do the same basic work. They scan configuration, map findings to a standard, and report the result. Doing this by hand, with open-source tools, shows what that work really is. Prowler checks the cloud account's posture, called CSPM, against standards such as the CIS foundations benchmark. Kubescape checks the cluster's posture, called KSPM, against hardening guidance. Inside-out platforms such as Mondoo cover both areas, and add fixing on top. See Inside-out exposure (Mondoo).

Before you start

# Prowler (Python 3.10 to 3.12)
pip3 install prowler
# Kubescape
curl -s https://raw.githubusercontent.com/kubescape/kubescape/master/install.sh | /bin/bash
PartMeaning
pip3 install prowlerInstalls the AWS scanner
`curl -s ... \/bin/bash`Downloads and runs the Kubescape installer. Read a script before you pipe it to a shell

Both tools reuse the credentials and kubeconfig you already set up.

Steps

cd phase4_ai_cnapp_incident/oss_cnapp

Step 1: scan the account with Prowler

prowler aws --output-formats html json-ocsf --output-directory ./prowler_results
PartMeaning
prowler awsScan the AWS account in your default profile
--output-formats html json-ocsfWrite a readable report and a standard JSON format
--output-directoryWhere to put the results

The scan takes a few minutes. Open the HTML file in prowler_results/.

Look for FAIL on: public S3 access, an over-broad role on the VM, and a security group that allows SSH from anywhere (check name ec2_securitygroup_allow_ingress_from_internet_to_port_22).

Step 2: scan the cluster with Kubescape

kubectl config current-context
kubescape scan framework nsa --format json --output ./kubescape_results/nsa-report.json
kubescape scan framework nsa --format pretty-printer
PartMeaning
kubectl config current-contextConfirm which cluster you are scanning
kubescape scan framework nsaCheck against the NSA and CISA Kubernetes hardening guidance
--format json / pretty-printerMachine-readable file, and a readable console summary

Look for failed controls about the cluster-admin binding in the tasky namespace, missing resource limits and network policies.

Verify

Prowler fails the three Phase 1 weaknesses, and Kubescape fails the cluster-admin binding.

Think about what was missed

The outdated MongoDB version is outside both scanners' scope: they read cloud and cluster settings, not software inside a VM. Finding it needs a vulnerability scanner or a workload scanner. This is why you combine tools.

Troubleshooting

SymptomLikely causeFix
prowler: command not foundNot installed or not on the pathReinstall and check your Python path
Kubescape scans the wrong clusterWrong kubectl contextaws eks update-kubeconfig --region us-east-1 --name wiz-exercise-eks

Clean up

Results are local files. Delete them if you share the folder.

Check yourself

  1. Which scanner finds the cluster-admin binding and which finds the open bucket?
  2. Name a weakness neither tool can see.
