1.1 Deploy the VM and MongoDB with Terraform

Time 30 to 40 minutesAWS cost Hourly charges for EC2 and NAT gateway; destroy when doneNeeds Prerequisites page done; sandbox cloud account (AWS in the examples)Source script Technical_Exercise/phase1_vm_mongodb

Goal

This lab runs in a cloud environment and uses AWS as the example. Create a virtual network, a VM running an old MongoDB, a backup bucket and an IAM role. Build all of it from Terraform code. Then log in and check it.

Why it matters

Terraform describes infrastructure as code. The same weaknesses can then be reviewed, scanned and fixed in code too. This phase plants four weaknesses on purpose. Cloud-security tools should find all four:

WeaknessFileSecurity area
SSH open to the whole internetsecurity_groups.tfCloud posture (CSPM)
VM role with far too many permissionsiam.tfIdentity entitlements (CIEM)
Public backup buckets3.tfData exposure and CSPM
Outdated OS and databaseec2.tf, scripts/mongo_setup.sh.tplVulnerability management

In exposure-management terms, the first and third weaknesses are what an outside-in scanner reports. The second and fourth are what an inside-out tool, such as Mondoo, reports. See PEM and the four perspectives.

Before you start

  • Done: Prerequisites and cloud account setup
  • Lab files: the phase1_vm_mongodb folder, opened in your terminal.

What is in the folder

FilePurpose
versions.tfPins Terraform and provider versions
variables.tfInput variables
network.tfVPC, public and private subnets, NAT gateway
security_groups.tfFirewall rules (SSH open on purpose; MongoDB only from the private subnet)
iam.tfVM role with AmazonEC2FullAccess (too broad on purpose)
s3.tfBackup bucket with public read and listing (on purpose)
ec2.tfUbuntu 20.04 VM (outdated on purpose)
outputs.tfValues printed after deploy
terraform.tfvars.exampleTemplate for your own values
scripts/mongo_setup.sh.tplInstalls MongoDB 4.4, turns on authentication, schedules the backup

Steps

Step 1: create an SSH key pair

aws ec2 create-key-pair --key-name wiz-exercise-key \
  --query 'KeyMaterial' --output text > wiz-exercise-key.pem
chmod 400 wiz-exercise-key.pem
PartMeaning
aws ec2 create-key-pairAsk AWS to create a new key pair
--key-name wiz-exercise-keyThe name AWS stores; Terraform refers to this name
--query 'KeyMaterial'Keep only the private key text from the response
--output textPrint it as plain text
> wiz-exercise-key.pemSave the output to a file. AWS shows the private key only once
chmod 400 ...Make the file readable only by you; SSH refuses keys with looser permissions
Warning: the .pem file is a secret. Do not commit it or share it.

Step 2: create your variable file

cp terraform.tfvars.example terraform.tfvars

Open terraform.tfvars and set your own values:

aws_region           = "us-east-1"
project_name         = "wiz-exercise"
key_pair_name        = "wiz-exercise-key"
mongo_admin_user     = "taskyAdmin"
mongo_admin_password = "<A_THROWAWAY_PASSWORD>"
VariableMeaning
aws_regionRegion to build in
project_namePrefix for resource names
key_pair_nameMust match the key pair from Step 1
mongo_admin_user, mongo_admin_passwordThe database admin account. Use a throwaway password

Step 3: initialize, plan and apply

terraform init
terraform plan
terraform apply
CommandWhat it does
terraform initDownloads the AWS provider and prepares the folder; run once per folder
terraform planShows what would be created, changed or destroyed. Changes nothing
terraform applyShows the plan again, asks for yes, then creates the resources

Expected: plan lists a VPC, two subnets, a NAT gateway, an EC2 instance, an S3 bucket and IAM resources. apply ends with Apply complete! and a list of outputs. Example:

Apply complete! Resources: <N> added, 0 changed, 0 destroyed.
Caution: do not use -auto-approve while learning. Reading the plan is the point.

Step 4: read the outputs

terraform output mongo_vm_public_ip
terraform output backup_bucket_public_url
PartMeaning
terraform output <name>Print one value that outputs.tf exposes

Step 5: log in to the VM and check MongoDB

ssh -i wiz-exercise-key.pem ubuntu@$(terraform output -raw mongo_vm_public_ip)
mongod --version
PartMeaning
ssh -i wiz-exercise-key.pemLog in using that private key
ubuntu@...Default user on Ubuntu images, at the VM's public address
$(terraform output -raw mongo_vm_public_ip)Run the inner command and paste its result here; -raw prints without quotes
mongod --versionPrint the MongoDB server version

Expected: db version v4.4.x. This old version is the point of the lab.

Step 6: check database authentication from inside the VM

mongo --username taskyAdmin --authenticationDatabase admin

You are prompted for the password. Typing it at the prompt keeps it out of your shell history. Port 27017 is open only to the private subnet, so this works from inside the VM but not from your laptop. That is correct.

PartMeaning
--username taskyAdminThe admin user you set
--authenticationDatabase adminThe database where that user is defined

Verify

  • terraform apply finished without errors.
  • SSH login works.
  • mongod --version shows 4.4.
  • Opening the backup URL in a browser returns an XML listing (it may be empty until the first scheduled backup runs).

Troubleshooting

SymptomLikely causeFix
Permissions 0644 ... are too openKey file permissionschmod 400 wiz-exercise-key.pem
InvalidKeyPair.NotFoundKey name mismatchMake key_pair_name match the name from Step 1
Connection timed out on SSHVM still starting, or your network blocks port 22Wait two minutes; try another network
AccessDenied during applyLab user lacks permissionsAllow EC2, VPC, IAM and S3 for the lab user

Clean up

Do not clean up yet: Phase 2 builds on this. When you finish all phases, follow Cost, safety and cleanup.

Check yourself

  1. Why does terraform plan come before apply?
  2. Which of the four weaknesses can an outside observer see without logging in?
  3. Why is it correct that the MongoDB connection from your laptop fails?
